# DECISIONS — 架构与产品决策记录

> 每条采用：编号 / 状态 / 决策 / 理由 / 影响 / 重新评估条件。状态：`Accepted` 已确认，`Proposed` 待验证。改动既有决定需要新增 ADR，不覆盖历史。

## ADR-001 — 单人本地使用

- 状态：Accepted
- 决策：不引入用户账户、多租户、社交与课程商业化功能。
- 理由：只给自己使用，降低维护成本。
- 影响：API 和页面默认一个使用者，但仍需保护本地上传和 API Key。

## ADR-002 — 用户自行在本地运行代码

- 状态：Accepted
- 决策：网页仅允许手动上传代码和日志，不实现在线 IDE、服务器执行或强制 CLI。
- 理由：不增加日常操作负担，兼容个人 IDE、GPU 和各类实验环境。
- 影响：评审为静态分析+日志辅助，不得宣称独立执行或验证。

## ADR-003 — Project 为核心组织单位

- 状态：Accepted
- 决策：Project 组织课程、资料、会话、提交和计划；基础知识可跨项目复用。
- 理由：同时学习不同领域且保持上下文边界。

## ADR-004 — 固定课程与自由学习共存

- 状态：Accepted
- 决策：固定路线保留核心目标；自由问答/论文导入按需增加临时内容。
- 理由：保证系统性与灵活性。

## ADR-005 — 自动知识沉淀、核心内容审核

- 状态：Accepted
- 决策：一般笔记自动生成草稿；核心公式、标准解法、评测规则及覆盖已确认内容须审核。
- 理由：降低操作负担，同时避免 AI 错误污染知识库。

## ADR-006 — 跨项目修改必须确认

- 状态：Accepted
- 决策：Agent 可主动生成建议，但不能未经确认更改其他项目的学习计划。
- 理由：保持其他项目学习节奏和用户控制权。

## ADR-007 — 一个主 Agent

- 状态：Accepted
- 决策：一个主 Teaching Agent 协调既有教学和明确的工具/服务，不引入多 Agent 团队。
- 理由：避免不必要的复杂度和调试成本。

## ADR-008 — 先 Fork 并保留 StudyForge 主技术栈

- 状态：Accepted（以本地基线验证为前提）
- 决策：优先复用 Next.js/React、FastAPI、SQLite 和课程/FSRS/Tutor，不先改成 Vue。
- 理由：减少重写和复用已存在功能。
- 重新评估条件：P0 测试表明上游功能不可稳定运行或维护成本明显过高。

## ADR-009 — Markdown + SQLite + 本地文件

- 状态：Accepted
- 决策：知识正文可维护为 Markdown；SQLite 管理关系和状态，原始资料保留在本地文件系统。
- 理由：易阅读、备份、扩展；暂不需要向量/图数据库。

## ADR-010 — 使用正式迁移机制

- 状态：Proposed
- 决策：涉及复杂表关系时采用 Alembic，保留 SQLite 升级与回滚测试；简单全新表可先安全增加。
- 理由：上游自定义迁移仅适合简单新增列。
- 确认条件：P1 开始前通过实际旧数据迁移演练。

## ADR-011 — 代码评审证据分级

- 状态：Accepted
- 决策：输出分别标记 confirmed_static、user_reported、inferred、needs_local_check。
- 理由：AI 没有执行上传代码，必须诚实表达证据强度。

## ADR-012 — 模型与文档来源可替换

- 状态：Proposed

## ADR-017 — 取消时间驱动机制，转向纯知识掌握驱动
- 日期：2026-10-20
- 状态：Accepted（用户明确指令）
- 背景：原 StudyForge 具备考试倒计时（Deadline）、可用天数（Days Off）、日历导出（ICS）及按日期的到期复习安排。
- 决策：
  1. 完全取消时间驱动功能：移除 Planning、Deadline、Days Off、Calendar 导出等产品功能；取消 56 天等固定周期的表述。
  2. 确立纯知识驱动闭环：选择项目 → 选择知识点 → 学习 → 本地代码实践 → 上传结果 → AI 静态检验 → 错因分析 → 补充练习 → 更新掌握状态。
  3. FSRS 底层实现与历史日志完整保留，但不按到期日期强制推送复习；复习由用户自主发起，或由 Agent 根据知识漏洞与错题推荐。
  4. 绝不删除或损坏已有的学习历史、答题记录与复习日志。
- 影响：前端导航与课程详情页精简（移除 Plan 标签、DeadlineForm、DaysOff 等）；后端保留底层数据表兼容，规划类接口降级或逐步下线。


## ADR-019 — 自由学习的检索、引文与练习边界
- 日期：2026-10-21
- 状态：Accepted（P3 定向与全量后端回归、前端 tsc/lint/test/build 通过）
- 决策：
  1. 会话（AgentSession）严格属于一个项目。检索只在该项目的 `resource_chunks` 内进行：先 FTS5，无命中时用有界的 LIKE 回退（覆盖 FTS5 分词漏掉的中文短语与带标点的提问）。跨项目检索会让“引文指向本项目资料”这句承诺静默失效，因此不做。
  2. 引文以标记（S1..Sn）给出，模型只能引用本次实际提供过的标记；未提供过的标记在落库前丢弃，不进入 `source_refs`。`source_refs` 是快照（文件名、定位、chunk id），不是外键：资料之后被删除，也不该把“有出处的断言”变成“无出处的断言”。
  3. 引用块不可被引用内容闭合：只改写精确的 `</SOURCES>`、`</CONVERSATION>`、`</QUESTION>` 令牌，不做全角括号替换，保证源码里的 `a < b` 原样保留。
  4. 模型调用失败或输出不可解析时不落库：问题不会留下一个没有回答的空壳，重试不会产生重复提问。
  5. 教学策略只有一个所有者：`app/teaching.py` 持有“先解释再提问”“两个回答字段”“四种情形”“共同拒绝项”“围栏段落”，Tutor 与自由学习共用；各端只保留自己成立的规则（Tutor 的调度器拒绝、guided 模式；自由学习的引文与不执行代码）。Tutor 的 system prompt 在抽取前后逐字节一致。
  6. 由提问生成的“临时讲解 + 练习”中，讲解作为助手消息入库（与回答同源的引文快照），练习进入 `variant_exercises` 并以 `draft` 保存，可通过既有提交入口 `variant_id` 关联；会话 id 与原始提问只作追溯，不设外键、不级联删除。
- 理由：引文正确性是这个功能的全部价值；证据边界（哪些是资料说的、哪些是模型知道的、哪些没被验证）必须由 schema 与界面共同承载，而不是靠提示词自律。
- 影响：单个问题的上下文有上限（5 段 / 6000 字符 / 6 轮历史），超长资料不会被完整送入；练习未经人工审核，界面必须标明“草稿、未运行”，不出现“已验证”表述。
- 重新评估条件：需要跨项目引用，或需要把自由学习结论沉淀为知识条目时（P4-01/02），另立决策，不在检索层放宽。

## ADR-018 — 提交与评审的存储与证据边界
- 日期：2026-10-20
- 状态：Accepted（P2 定向测试与全量后端回归通过）
- 决策：
  1. `SubmissionArtifact` 的文本内容存入 SQLite（代码 512KB、日志 2MB 上限），不落独立文件；备份一份数据库即完整备份提交记录。
  2. 上传文件与粘贴文本走同一套校验：扩展名白名单、大小上限、UTF-8 严格解码、拒绝二进制与含路径的文件名；只解码与静态解析，没有任何执行路径。
  3. 评审证据固定四类：`confirmed_static`（源码可证）、`user_reported`（用户日志声称）、`inferred`（静态与日志的相关性推断）、`needs_local_check`（需本地验证）。无日志时必给一条 `needs_local_check`，不把“未检查”写成“没问题”。
  4. 模型评审默认关闭，按需开启；模型失败或输出不合契约时降级为静态评审，并以 `llm_status=unavailable` 如实标注，不静默冒充 AI 结果。
  5. 二、三级提示与参考解法必须单独请求；参考解法一律标注 `ai_generated_unverified`。
  6. 变式题以 `draft` 保存，生成失败返回 502 而不是伪造题目；后续提交可通过 `variant_id` 关联草稿。
- 理由：整库备份最简单；避免在个人目录散落小文件与清理风险；证据分级与提示阶梯是产品硬约束，不能由响应体默认泄露。
- 影响：单个提交不适合承载超大文件（如完整训练日志 > 2MB），超出时提示用户裁剪；模型评审与变式题消耗额度，故均为显式动作。
- 重新评估条件：需要保留原始二进制附件，或单文件上限成为真实障碍时，引入独立资料目录与引用计数清理。

## ADR-020 — 知识草稿、审核版本与错因证据
- 日期：2026-10-21
- 状态：Accepted（P4-01/02/03 定向验收完成；P4-04 后端完成，前端待集成）
- 决策：知识正文和不可变版本统一存 SQLite；有引用的回答/讲解在会话事务内自动保存普通草稿，不再次调用模型，也不提升掌握等级。beyond 扩展不提升为有来源笔记。
- 去重：同标题复用已有条目，相似条目仅返回候选；任何自动化路径不覆盖已确认内容。
- 审核：核心定义/标准答案初始待审核，确认是独立操作；编辑确认稿退回待审核并追加版本。浏览器必须携带读取时的更新时间，409 时保留草稿，明确选择后才能丢弃本地编辑。旧调用方可继续使用无令牌接口，无法获得乐观并发保护。
- 错因：手工诊断不能标成已验证答题或提交证据；专用错题端点核验所属课程和错误答案。错因队列只读 FSRS，Again 不关闭任务。日期只用于审计先后，不用于安排学习。
- 影响与限制：当前仅有知识页，错因/复习任务前端与提交证据专用端点未完成；跨项目建议必须等待 P4-05 用户确认流程，不从错因服务直接写其他项目。
- 验证：后端知识/错因/Agent 74 项、迁移 24 项通过；前端知识审核 10 项及 tsc/lint/build 通过，详见 PROGRESS。

## ADR-021 — 评审错因与项目主动复习
- 日期：2026-10-21
- 状态：Accepted（P4-04 定向后端 75 项、前端 14 项与类型/lint/build 通过）
- 决策：评审缺少标准化概念键，由用户选择知识点，不能把模型 category 当作已确认知识。证据从服务器已存 finding 快照取得，验证评审所属项目，拒绝客户端证据正文及只有待本地检查的提示。
- 主动复习：只按本项目开放错因和关联课程取题，不按 due 过滤，不创建卡片；没有现成题目和卡片时明确提供学习/本地实践路径。共用既有 ReviewSession、答题与自评接口，主动模式隐藏学习间隔。
- 证据边界：后续有效自评可以关闭此前复习建议，界面明确“不代表代码已修复”。不通过聊天或诊断修改掌握度/FSRS。忽略只处理最新一条错因，保留记录，仍有其他错因时任务继续存在。
- 限制：证据 detail 最多 4000 字符，超长 finding 快照可能截断，不能承诺完整原文（完整评审仍存 CodeReview）。已打开页面仍沿用全局课程复习接口，归档只阻止新增诊断与项目新入口；共享概念的个人复习历史继续保留。旧全局 Today/Review 的日期驱动展示在 P5 集中处理。

## ADR-022 — 跨项目建议的确认与事务边界
- 日期：2026-10-21
- 状态：Accepted（P4-05/06 定向验证通过）
- 决策：由用户从开放错因选择目标项目，保存 pending 建议及不可变证据快照；创建和拒绝不写目标项目。只有 accepted 决定才在目标创建知识驱动复习任务，不改课程顺序或 FSRS，不设置日期。
- 一致性：同一错因/目标有唯一约束；SQLite 写锁后刷新决定状态，同决定重试幂等、相反决定 409。目标任务和建议接受状态一同提交，插入后失败整体回滚。
- 追溯：保留来源错因/项目、概念、证据、决定时间及目标任务 ID。逐条判断来源错因是否已复习或忽略，不因新出现同概念错误而复活旧证据。
- 归档：来源或目标归档均阻止接受；拒绝仍可处理建议。无需删除任何历史。现有核心内容和其他项目安排在用户接受前保持不变。
- 边界：当前目标由用户选择，未添加自动目标匹配或额外模型调用；创建建议和接受建议是两个明确操作。证据最长 4000 字符，目标任务表示确认的复习需要，不表示目标项目实测失败。

## ADR-023 — 只读课程知识树与练习进阶建议
- 日期：2026-10-21
- 状态：Accepted（P5-01 后端 6 项、前端 14 项及类型/lint/build 通过）
- 决策：知识树派生既有课程、课时、概念及项目知识关联，不新建重复历史实体。教材别名只映射阅读，不合并原始概念键；章节顺序不是前置关系。前置知识来自显式关联及人工配置的教学建议，所有节点可自由打开。
- 证据：只取项目课程内每题首次 lesson_quiz 和 review_session 作答，排除重试与 remedial_practice。最近三条正确、跨至少两题才建议进阶；开放错因或最近正式错答优先推荐复习。ready_for_advanced 不是 mastered，不写掌握、FSRS 或任何历史；时间流逝不自动降级。
- 教材：D2L 中文版白名单已核实 2.1 数据操作（含广播）、2.3 线性代数、2.5 自动微分、10.3 注意力评分函数、10.7 Transformer。未知主题不推测章节，视觉 Token/多模态/Radar/VLM 明确作为扩展路径，不声称完整内容已经创建。
- 交互：推荐基础/巩固/补先修/进阶/综合，准备提问时只建立空会话和可编辑草稿，用户发送才调用模型。原始资料与已存标题保留原文，应用文案双语。
- 限制：条目层无环关系合并概念后可能出现推荐环，目前仅展示建议且不锁课；未来自动排序前需检查投影环。只在错因记录、未进入课程/知识条目的概念仍在错因页查看，不声称本树覆盖全部诊断。

## ADR-024 — 内容审核只对确定的来源版本生效
- 日期：2026-10-21
- 状态：Accepted（审核机制定向验证完成，P5-02 内容核对仍进行中）
- 决策：从项目关联课时或已经主动揭示的参考解法建立 pending_review 快照，沿用 KnowledgeEntry 的人工编辑、确认、版本机制；不通过导入自动确认，不修改原文，不执行任何解法。

## ADR-025 — 流式课程生成端点与 main.py 共处
- 日期：2026-10-21
- 状态：Accepted
- 决策：`POST /courses/generate/stream`（SSE）放在 `backend/app/main.py`，与既有的 `/courses/generate`、`/courses/generate/pdf`、`/courses/generate/multipart` 同文件。AGENTS.md 要求新业务独立模块、避免 main.py 膨胀，但流式端点复用 main.py 内 helpers（`_ingest_or_refuse`、`_save_course`、`_cost_limit_exceeded` 语义、`generation`/`ingest` 装配），抽离需整体搬运 4 个端点的共享装配，得不偿失；既有格局本就是 4 个 generate 端点同文件。
- 追溯：并行 lesson 生成线程安全——provider 每次调用新建 httpx 连接，`MeteredLLM._record` 每次开独立 DB session；请求级 session 只在流结束后的 `_save_course` 使用。失败一节不中断全程（`lesson_failed` 事件），与同步路由 drop-one-keep-rest 一致。
- 前端：文本/URL 来源走流式（`GenerationProgress` 渐进渲染）；PDF 仍走同步 multipart（流式 multipart 未做）。

## ADR-026 — 独立浅色首页与统一的双主题
