# PRD — Personal AI Learning Agent

版本：1.0（开发需求基线）  
产品形态：本地自托管、单用户、项目化学习工作台  
实现状态：**需求文档，非已交付功能**

## 1. 产品目标与成功标准

让用户以最低额外操作负担，在统一工作台完成：**学习 → 本地编程 → 上传代码/日志 → AI 静态审查 → 错因定位 → 补课与变式题 → 复测 → 知识沉淀**。

**成功标准（MVP）：** PyTorch Tensor 广播案例能从课程学习走到二次提交；模型能指出代码中可证实的维度错误、基于用户日志解释运行症状、区分未经执行结论；原题和变式题均能归档并关联知识点。

## 2. 用户及边界

- 用户：仅本人，无账号体系、权限/组织/社交模块。
- 设备：本地 Windows/Linux IDE、现有 Python/Conda/uv/GPU 环境；网页独立运行。
- 提交：手动上传 `.py`、`.txt`、`.log`、必要的配置或 `.zip`；可复制粘贴代码/输出。
- 网站**不执行**代码，亦不提供强制本地 CLI。输出评测仅为静态分析和用户自报运行证据分析。
- 不做在线 IDE、远端 GPU、自动训练、多人协作、排行榜。

## 3. 信息架构与页面

### 3.1 首页 `/`

- 我的项目卡片、最近打开项目、今日课程、待复习知识、最近提交。
- 「创建项目」「继续学习」「自由学习」「添加资料」快捷入口。

### 3.2 项目首页 `/projects/:id`

- 目标、课程进度、最近活动、资料、当前知识薄弱点。
- 导航：概览、学习、AI 导师、知识库、代码评审、学习记录。
- 创建项目仅必填名称；课程型/研究型/实践型为可随时改变的初始模板。

### 3.3 课程工作台 `/projects/:id/learn/:lessonId`

- 左侧课程导航，中间：数学原理、形状说明、代码示例、练习与上传；右侧项目 AI 导师。
- 首个课程：56 天 PyTorch → Attention → 视觉 Token → 多模态 → Radar → VLM 路线。
- 固定的核心章节、公式、参考解法和验收条件需经过确认；AI 可补充解释和练习。

### 3.4 自由学习 `/projects/:id/explore`

- 直接输入问题、上传论文/代码/日志、选取项目内资料。
- Agent 引用可用来源回答，自动建议先修知识、生成可运行的本地练习文本。
- 自由学习记录自动生成知识草稿；不能随意打乱固定课程。

### 3.5 提交与代码评审 `/projects/:id/submissions/:submissionId`

- 代码/日志预览、项目关联、版本历史、错误类别、明确证据、分级提示、参考解法、复测提交。
- 报告显式区分：源码可确证 / 用户日志声称 / AI 推断 / 待本地验证。
- 标准答案可主动查看，但未经确认的 AI 生成答案不能冒充已验证参考解法。

### 3.6 知识库 `/projects/:id/knowledge` 和全局知识页

- 来源：主题生成、PDF/DOCX/Markdown、网页/GitHub URL、学习对话沉淀。
- AI 自动去重、组织知识草稿、关联前置依赖；项目特定知识与全局基础概念区分。
- 内容状态：draft、pending_review、confirmed；正文保留来源标注。

### 3.7 复习与建议 `/review`

- 错题按知识根因组织；复习可跳回原项目。
- 跨项目修改只能生成待确认建议；确认后才更新目标项目任务。

## 4. 三个关键用户流程

### 4.1 PyTorch 课程学习闭环

1. 阅读 Day 1 Tensor 广播知识与练习。
2. IDE 本地编写并运行，手动上传 `solution.py` 和 `output.txt`。
3. 解析文件、关联任务，做静态分析和日志辅助 AI 诊断。
4. 输出具体错误证据、一级提示，按需提高提示层级。
5. 用户修改后再次上传；Agent 给变式题。
6. 用户独立复测；保存结果及知识状态（不将自报结果视为云端验证）。

### 4.2 SPDM 自由学习闭环

1. 在「多模态 Token 对齐」项目上传论文，保存原文件及可定位来源片段。
2. 询问「SPDM 为什么需要 Shared/Private 分解」。
3. Agent 按论文内容解释重构、去相关与模态判别；补充非论文内容时明确标记。
4. 根据知识漏洞生成 PyTorch 练习。
5. 相关问答整理成项目知识草稿；核心定义待审核。

### 4.3 跨项目补课闭环

1. 当前论文项目多次出现矩阵乘法问题。
2. Agent 生成「建议去 PyTorch 项目复习矩阵乘法」卡片。
3. 用户确认后才创建另一个项目的复习任务；拒绝则不修改。

## 5. 业务需求及验收

| ID | 需求 | MVP 验收 |
|---|---|---|
| P01 | 项目 CRUD | 可创建、修改、归档多个项目，互不混淆 |
| P02 | 课程复用 | 既有课程、测验、复习流程不回归 |
| P03 | 资源持久化 | 上传 PDF 可再次打开，AI 能引用片段位置 |
| P04 | 手动代码提交 | 文件、日志或文本可上传，保留多次版本 |
| P05 | AI 代码评审 | 错误关联到具体行、Shape、证据级别 |
| P06 | 渐进提示与参考答案 | 提示等级可控，完整答案需主动触发 |
| P07 | 补课与变式题 | 能针对广播错误生成相似但不完全重复的练习 |
| P08 | 自由学习 | 论文问答能关联 Project 资料和知识草稿 |
| P09 | 知识审核 | 普通草稿自动保存，核心条目需确认 |
| P10 | 跨项目建议 | 未确认不得修改其他项目计划 |
| P11 | 学习历史 | 原提交、提示、复测、来源可追溯 |
| P12 | 本地隐私 | 可删除上传文件和记录，不上传密钥 |

## 6. 教学策略

- 默认采用分层提示：线索 → 数学/维度解释 → 关键修复；可自选直接讲解和代码规范审查。
- 不强迫苏格拉底式回答；用户可主动选择完整答案。
- 代码评审结论应引用可见源码和日志证据，不能谎称执行成功。
- 学习状态建议采用 `unassessed / learning / needs_review / mastered`，避免未经验证的精确评分。
- 对复习和课程系统沿用 StudyForge 的有效机制；新代码练习不得随意篡改 FSRS 复习状态。

## 7. 非功能要求

- 自托管易启动；个人电脑资源占用低；无强制 CLI 和远程服务。
- 输入安全：文件大小上限、白名单、路径检查、脱敏提示、禁止执行上传代码。
- 数据可备份、可恢复、可按项目导出 Markdown；必须保留来源追踪。
- LLM 请求失败不影响已有项目和资料浏览；流式对话可作为增强能力。
- 保留原项目许可证与必要声明；资料导入尊重第三方版权。

## 8. 不属于 MVP

多用户、在线运行、浏览器 Python、GPU 调度、自动修改本地代码、复杂知识图数据库、多 Agent 团队、自动重写已确认课程、完整 56 天课程内容一次性批量生成并无审核上线。

## 9. 里程碑

M0 上游测试跑通；M1 Project/Resource；M2 上传和静态评审闭环；M3 自由学习；M4 知识沉淀与跨项目建议；M5 56 天课程逐步覆盖、整体回归。详细任务见 `TASKS.md`。
